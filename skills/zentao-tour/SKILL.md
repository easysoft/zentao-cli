# 禅道 Tour

像同事陪用户认识自己的禅道：先了解他眼下要做什么，再用少量真实例子把对象和工作流串起来。角色文件是线索地图，不是必须执行完的剧本。用户只想了解时，可以靠离线帮助和示例讲清楚，无需登录或创建数据。

## 开场与选路

用一两句话说清这段路，例如“先看看你手上的需求，再试着把下一版的范围整理出来”。从上下文已知的角色、产品或问题切入，不重复问已回答的问题。

需要连接真实环境时，按 [overview.md](overview.md) 检查本地配置，再做一次小范围只读请求。`zentao profile` 只展示本地账号配置，不能证明登录仍有效、服务可达或账号具有什么角色。只有角色不明确时，才问用户平时主要负责哪块；可用当前环境可用的提问工具，或直接自然语言提问，不依赖特定 Agent 工具名。

| 用户关心的事 | 按需读取 |
| --- | --- |
| 产品想法、需求与计划 | [roles/pm.md](roles/pm.md) |
| 项目排期、执行与分工 | [roles/pjm.md](roles/pjm.md) |
| 用例、测试单与缺陷回归 | [roles/test.md](roles/test.md) |
| 我的任务、工时与 Bug | [roles/dev.md](roles/dev.md) |
| 项目和产品的整体情况 | [roles/executive.md](roles/executive.md) |

“随便看看”时，给两三个贴近用户背景的入口，让他挑感兴趣的一个。每次只读需要的角色文件；安装、MCP、版本问题再查 overview，完整命令规则查 [zentao-cli 技能](../zentao-cli/SKILL.md)。

## 对话节奏

- 开场顺口说明路线；每次推进一个有意义的动作或问题，不把全部流程念成任务清单。
- 解释用用户的业务词汇，再补必要的字段名。例如“这条任务准备交给谁，对应 `assignedTo`”。
- 反馈要具体：指出需求场景是否清楚、缺了哪项信息、查询说明了什么。避免固定的赞美、夸张口语和每段都问“要不要继续”。
- 记住已选账号、范围、当前进度、写入授权和创建的对象 ID。用户改方向时顺势切换，不要求走完当前路线。

## 实际操作规则

**范围与授权**：先复用用户指定的产品、项目、执行或演示区。“体验一下”本身不授权修改已有记录；需要写入但范围未明确时，把目标对象和拟改内容说明白再取得授权。用户已明确要求或已批准的操作直接执行，不逐条重复确认。按用户批准的批次处理也可以，不强制一次只写一条。

**业务状态**：真实任务仅在确实开始或完成后流转；真实 Bug 仅在有修复、解决或回归依据后流转。仅讲解流程时展示命令即可；需要演练完整生命周期时，限定在用户已授权的演示数据内，不编造实际工时、修复或回归结论。

**命令与版本**：先按需查看 `zentao <module> <action> --help` 的参数与最低版本。`props` 是返回对象字段，不代表可写字段；`my` 等模块需要明确操作名。业务参数优先 `--key=value`，嵌套结构和数组用 JSON。文中的 `<...>` 都要替换为实际值，不能原样执行。

**结果与重试**：依据返回的成功/失败状态和实际 ID 继续。返回不足以确认结果时，使用该模块支持的详情或列表查询核实，再告诉用户改成了什么；有些模块没有 `get`。超时或返回不明的写请求先检查对象现状，不盲目重试创建、完成、解决或删除。批次部分失败时只汇报已确认成功的项目。

**列表与统计**：展示一页候选可以；需要“全部”“没有”“总数”“最早/最近”或全局排序时，要覆盖约定范围的全部分页。`--filter`、`--sort`、`--limit` 只处理当前页，筛选后为空不等于后续页也为空。按服务端 pager 继续翻页，再本地汇总；没有完整数据时明确已读范围。不能用 `--all` 代替翻页，也不能将单个 `--filter` 中互斥的条件当作 OR。

## 出错时继续给出可走的路

| 错误 | 处理 |
| --- | --- |
| E1001 / E1004 / E1006 | 凭证缺失、失效或没有本地账号。让用户在自己的交互终端运行 `zentao login`，不要索取或回显密码、Token。已有安全注入的环境变量可按 overview 使用。 |
| E2001 / E2005 | 模块或操作不支持，查本地帮助，不猜接口。 |
| E2002 | 可能是对象 ID、范围或接口路径问题；核对请求与列表，不立即判定对象被删。 |
| E2003 / E2004 / E2007 / E2009 | 按操作帮助核对必填字段、参数类型或 JSON。 |
| E2006 | 当前账号无权访问。说明具体受限范围，可换一个有权查看的对象；不能把权限不足算成零条。 |
| E2010 | 当前禅道版本不支持该操作。查最低版本，使用角色文件中的兼容查询，或继续离线讲解。 |
| E2011 / E2012 | 服务版本格式或站点配置无法识别，核对服务地址及配置响应；不绕过版本检查继续写入。 |
| E1002 / E5001 / E5002 | 地址、连接、超时或证书问题。说明实际失败点，保留已取得的进度；写请求按上文先核实再重试。 |

向用户解释实际影响和下一步，不只复述错误码。

## 切换与收尾

尊重“停”“够了”“换一个”。结束时用一两句回顾实际看过、创建或修改过的内容，区分仅展示的命令与已执行动作。

默认保留数据。只有用户要求清理时，列明本次创建的演示对象、依赖关系和删除范围；在已有删除授权内执行 `zentao <module> delete <id> --yes`，没有覆盖该范围时再征求一次确认。不能因为名字像示例就删除，也不能把演示结束当成关闭真实任务或 Bug 的理由。
